# Connectify System & Styling Modules Reference

This document covers notifications, grade change tracking, DOM integrity monitoring, navigation injection, dark theme surface adaptation, auto-login, stylesheets, and extension manifests.

---

## 2. Module Reference: System, Theme & Styles

### System Health, Navigation & Theme

#### `scheduler.js` (`ConnectifyScheduler`)
- **Role**: One page-wide MutationObserver and one heartbeat shared by every isolated script; loaded first in each isolated group (first copy wins); disconnects on `pagehide`, resumes on a back/forward `pageshow`.
- **Key Functions**: `onMutations(callback, { filter, mute = true })` (records batched per animation frame, per 100ms while hidden); `every(ms, fn, { whenActive = true, whenVisible = true, mute = false, when })`; `isMuted()`. Sidebar sync (handle position reads layout), tools sync, `syncFeatures` and the 8s cohort pass are muted, so Expand All never forces a page layout mid-run.

#### [`notifications.js`](file:///Users/uwong/Downloads/2.1.14_0/src/system/notifications.js)
- **Role**: Universal notification and toast manager for Connectify.
- **Key Functions**:
  - `show({ id, type, title, message, details, actions, duration, dismissible, onDismiss })`: Mounts toast notifications into `#connectify-notifications-container`.
  - Supports types (`warning`, `success`, `info`, `grade`) with tailored theme colors, icons, and smooth slide-in/dismiss animations.
  - Automatically stacks concurrent notifications vertically (`flex-direction: column-reverse`).
  - Action button dispatcher supporting custom callbacks with `{ id, element, close }`.
  - `dismiss(id)` and `clearAll()`: Smoothly animates out and cleans up DOM elements.
- **Export**: `window.ConnectifyNotifications`.
- **`update-reload.js`** (background: Firefox `background.scripts`, Chrome `service_worker`; GitHub and Firefox builds only, both publish workflows strip it, `background` and `host_permissions` from the Chrome Web Store zip): on `runtime.onInstalled` (`install` / `update`, never browser updates) reloads every open `https://connect.det.wa.edu.au/*` tab, because tabs open during an update keep the old version's DOM with dead listeners until refreshed.
- **`update-notice.js`** (`ConnectifyUpdateNotice`): 3s after load, compares the manifest version with `connectify:seen_version`; a newer version shows one persistent "Connectify updated to X" toast (Dismiss / "What's new" → GitHub `CHANGELOG.md`, newest release first). Fresh installs only record the version; downgrades never notify.

#### [`new-grade.js`](file:///Users/uwong/Downloads/2.1.14_0/src/system/new-grade.js) & `grade-snapshot.js`
- **Role**: Grade change detection against `connectify:grade_cache:<student>`, once per page.
- **Key Functions**:
  - `grade-snapshot.js` (`ConnectifyGradeSnapshot`): `currentEntries()` reads each subject's running mark, the later semester's card first; `hasSubjectChanged(prev, entry)`: the student's own mark moved $\ge 0.05\%$ against a cached mark from the same semester's card. The cohort boxplot never counts (classmates getting results back moves it while the student's result is still unmarked).
  - `checkGrades()`: waits up to 5s (`MARK_WAIT_MS`) for every outline's summary mark; an empty cache is seeded quietly; an earlier semester's mark never replaces a later cached one; a results version bump keeps the grade cache (`clearResultsCache({ keepGrades: true })`), so a result released meanwhile is still announced (Clear Cache and the new-year rollover clear it); it then starts `grade-tasks.js` (`ConnectifyGradeTasks`): 1.5s after task rows appear (the student opening an outline, Expand All, auto-expand) each shown card's marked task ids (`cardTaskIds`) are compared with `tasks[<semester>]`; more newly marked ids than vanished ones (a rename swaps one) is a new result even when the mark stayed put; unseen cards are saved quietly, and a subject the mark check announced has its ids reset so opening it never repeats the notice; each changed subject is marked stale (re-scraped on its next expansion) and announced with a stacked "Class Updated" toast ("[Subject name] scores have been updated."). The cache is rewritten 1 second later.
  - `jumpToSubject(card)`: on the student's click, expands the card if collapsed, then scrolls and pulses `.cx-card-jump-highlight` in the next frame (no forced reflow, so the expand lays out once); the re-scrape and prediction refresh run 500ms later when idle (after the accordion animation), so the click never janks.
- **Export**: `window.ConnectifyNewGrade`.

#### [`dom-sweeper.js`](file:///Users/uwong/Downloads/2.1.14_0/src/system/dom-sweeper.js)
- **Role**: Health monitor that sweeps the DOM for injected Connectify components.
- **Key Functions**:
  - `inspectDOM()`: Sweeps for sidebar, toggle handle, data bridge, and assessment row panels. Properly ignores unmarked/incomplete tasks which intentionally do not render statistics panels, and omits the WACE countdown banner from missing component notices.
  - `sweep()`: skipped while accordions animate or Expand All runs; a miss triggers a cohort pass and is only reported if still missing 3s later (panels for newly rendered rows are drawn by the debounced pass).
  - `promptUser(missingItems)`: Dispatches warning notice via `window.ConnectifyNotifications.show()`.
  - `restoreComponents()`: Auto-triggers reinjection across `ConnectifyInitSidebar`, `ConnectifyCohort.pass()`, `ConnectifyCountdown.update()`, and `ConnectifyCompoundProgress.update()`.
- **Export**: `window.ConnectifyDomSweeper`.

#### [`navigation.js`](file:///Users/uwong/Downloads/2.1.14_0/src/system/navigation.js)
- **Role**: Injects direct "Assessment Outlines" shortcut into Connect navigation bar, tracks user activity, and detects session timeouts.
- **Key Functions**:
  - Injects link into desktop greedy navigation and mobile drawer.
  - `ConnectifyNavigation.markActive()`: on the outlines page moves Connect's `eds-s-is-active` from My Connect to the shortcut (desktop and drawer), restoring it elsewhere; re-run on nav re-renders and class changes.
  - Tracks user activity (`mousemove`, `keydown`, `scroll`) to update `window.__connectifyLastActive` and provide `window.ConnectifyIsUserActive()`.
  - Monitors session expiry modals and unloads while idle (> 5 min) to set `cx-session-expired`.
  - Intercepts manual logout clicks to set `cx-manual-logout`.

#### Theme scripts (`src/theme/`, manifest order)
- **`theme-auth.js`** (`ConnectifyThemeAuth`): login/logout URL detection, `markAuthPage()`, and `rememberThemeForLogin()` / `forgetThemeForLogin()` / `takeThemeToRestore()` for restoring the dark theme after sign-in.
- **`theme-custom-tokens.js`** (`ConnectifyThemeTokens`): custom tokens (incl. `--cx-card-bg`, `--cx-nav-bg`) written inline on `<html>` and `<body>`, cleared before each apply; wallpaper stored in `localStorage` with a `chrome.storage.local` fallback for over-quota images (restored on load); the Settings wallpaper (`get/setCustomBackground`) and the active theme's own (`setThemeBackground`, never stored), which wins on screen (`getActiveBackground`); glass toggle.
- **`theme-wallpaper-dim.js`** (`ConnectifyWallpaperDim`): `update(url)` (called by `applyCustomBackground`, and on load) samples the wallpaper (GIF: first frame) at <= 160px and bisects the least black overlay keeping white text >= 4.5:1 on every sample (`dimFor`, `--cx-wallpaper-dim`) and the least white overlay keeping the theme's dark `--cx-text-primary` >= 4.5:1 (`brightenFor`, `--cx-wallpaper-brighten`, recomputed on `connectea:themechange`), cached per wallpaper and ink (`connectify:wallpaper_dim`); unreadable images use 0.45. `theme-wallpaper-layer.css` paints the wallpaper as a fixed `html::before` layer (blur 2px, dim with light ink, brighten with dark ink, hidden in solid reading views).
- **`theme-palettes.js`** (`ConnectifyThemePalettes`): the 7 preset palettes (Dark, Quantum Dark, AMOLED, Midnight, Forest, Liquid Glass, Liquid Tinted Glass). Liquid Glass (`liquid-glass-clear`) is `derived`: it carries only 6 basic colours, and the registry applies it through the custom-token path (derivation + glass tokens at 30%) without touching the stored custom palette.
- **`theme-wallpaper-presets.js`** (`ConnectifyWallpaperPresets`): six geometric gradient wallpapers (facets, orbs, bands; three dark, three light) as SVG data URIs; `mount(container, onPick)` renders the Settings thumbnails, `find(url)` names the active one, `byId(id)` resolves a theme's `wallpaperPreset` (the registry applies it on `setTheme`; saved themes and `.ctme` files carry only the id).
- **`theme-wallpaper-fit.js`** (`ConnectifyWallpaperFit`): `fromFile(file, { adjust })` rescales an upload (`prescaleSize`: no more than the 300% crop can use), lets `adjust` (the crop prompt) pick the crop (`cropRect(iw, ih, tw, th, zoom, cx, cy)`; centred `fitRect` without it; null rejects with `code: 'cancelled'`, `isCancelled`), then crops it to the screen's aspect and scales it to its device pixels (DPR <= 2, long edge <= 3840) as a JPEG (0.86) before Settings or the customizer store it, decoding and resizing off-thread (`createImageBitmap`); small images that already fit keep their encoding; GIFs are always stored as uploaded so animated wallpapers keep every frame, up to `gifMax()` (40 MB with the `unlimitedStorage` permission, 4 MB in Chrome Web Store builds, whose zip has it stripped by both publish workflows); larger ones are refused with `errorText(err)` shown in the upload status. `fromDataUrl(url)` does the same for a stored or imported data URL (fetch, else atob, to a Blob; the original is kept when the fit is not smaller); `needsFit(url)` is true only for raster data URLs over 1.5 MB (never SVG presets or GIFs). The customizer's JSON import fits a large wallpaper before previewing it. Wallpapers paint `center / cover fixed`, so nothing visible is lost.
- **`theme-wallpaper-crop.js`** (`ConnectifyWallpaperCrop.prompt({ source, width, height, target })`): Settings' and the customizer's upload step between rescaling and cropping: `#cx-wallpaper-crop` (solid dialog, `theme-wallpaper-crop.css`) shows the rescaled image in a screen-shaped canvas frame; Size 100–300% (slider, wheel, trackpad pinch), drag to place (pointer capture), Reset; Use Wallpaper resolves to the `cropRect`, Cancel / Escape / outside click to null (the upload is cancelled, no error shown). Clicks never leave it, so the sidebar's outside-click keeps Settings open. GIFs skip it.
- **`theme-boot.js`** (`ConnectifyThemeBoot`, document_start): `save()` (from `setTheme`, `applyCustomBackground` and the wallpaper overlays, coalesced per task) snapshots `<html>` into `connectify:theme_boot`; on load the snapshot is stamped back (only theme attributes and `--cx-*` tokens, same theme id, not on auth pages) with a `#cx-theme-boot` canvas style that `theme.js` removes (`done()`). `cssUrl(url)`: Chrome drops CSS `url()`s over 2 MB, so larger data URLs become a cached `blob:` URL (Chromium only; the last two kept).
- **`theme-wallpaper-migrate.js`** (`ConnectifyWallpaperMigrate`): once per profile (`connectify:wallpaper_fit_done`, top frame, 5s after load when idle, never on login pages), fits the active wallpaper (`connectea:custom_background`, localStorage or extension storage) and every large `wallpaper` in saved custom themes (`connectea:custom_themes_list`, both stores merged by id), each distinct image once, and stores them back in place (`setCustomBackground`, registry `writeCustomThemes`, registered definitions); a wallpaper changed or cleared meanwhile is left alone.
- **`theme-registry.js`** (`ConnectifyThemeRegistry`): registry, `getTheme()`/`setTheme()`/`getLastTheme()`; `setTheme()` stamps classes and `data-connectea-theme` on `<html>` and `<body>` and fires `connectea:themechange`; `themeWallpaper(theme)` (preset by id, else its image) goes to `setThemeBackground`, so a theme's own wallpaper shows only while it is active.
- **`theme-custom-themes.js`**: saved custom themes (`getCustomThemes`, `saveCustomTheme` overwrites by case-insensitive name, `deleteCustomTheme` removes from both stores; saves are stamped `tokenVersion: 2`, and older themes drop the six tokens the 14-token Full mode could not edit so they are re-derived instead of keeping preset leftovers); re-applies a theme only found in extension storage.
- **`theme-oklch.js`** (`ConnectifyThemeOklch`): hex <-> OKLCH, `shiftL` (lightness step keeping hue and chroma/lightness ratio, gamut clamped), WCAG `contrast`, `ensureContrast`, `readable`.
- **`theme-token-derive.js`** (`ConnectifyThemeDerive`): fitted to the presets. `deriveFull()` maps the 6 Basic tokens to the 20 Full ones (e.g. surfaceHover = surface +11 L, borderSubtle = border -10.5, inputBg = canvas +1.5 towards the surface, textMuted = text -26 in the surface hue); `complete()` fills only missing ones; `cssProps()` derives every rarer `--cx-*` from the Full tokens (nav, table, badge, scrollbar, focus, primary button darkened until white text reaches 5:1). Text tokens are used as given (derived ones are already >= 5:1, a user-set colour is never contrast-swapped); ink on fills without a text token (accent, primary button, avatar) is the theme's own text when it reaches 5:1, else `readable()`. Applied by `applyCustomTokens` and the customizer preview.
- **`theme-glass-tokens.js`** (`ConnectifyThemeGlassTokens`): `props(c, opacity)` turns a custom theme with Liquid Glass on into a recoloured Liquid Glass theme (fills = its surface/canvas at the Transparency opacity scaled like the preset; overlays = its text colour at the preset's strengths; glass shadows). Default blur 12px.
- **Customizer** (`ConnectifyThemeCustomizer`): `theme-color-utils.js` (colour parsing, escaping, `pickColors`), `theme-customizer-markup.js` (escaped modal HTML, Basic 6 / Full 20 tokens, preview elements tagged `data-cx-fill` / `data-cx-text`; `#cx-preview-tooltip` names the text token when the pointer is over glyphs), `theme-customizer-popover.js` (`ConnectifyCustomizerPopover`: the picker as a popover anchored to the clicked token; its hue slider covers 0–360 over the whole track, the gradient laid along the thumb's travel, and dark themes' text-input padding skips range inputs), `theme-customizer-tokens.js` (`ConnectifyCustomizerTokens`: Full tokens the user set and a picked preset's own colours (`fromPreset`) are overrides in both modes, each held against what the Basic tokens derived for it when set (`bases`, `track`) and re-derived once a Basic token change alters that; ↺ in Full mode resets one; non-overrides are re-derived on every refresh; themes save Basic + overrides, and reopening recovers overrides as the tokens that differ from what the Basic ones derive), `theme-ctme.js` (`ConnectifyThemeCtme`: `.ctme` theme files, a ZIP named `fileName(name)` ("Test Theme" -> `test_theme.ctme`) of `theme.json` + `wallpaper.<ext>`; written stored, read stored or deflated (`DecompressionStream`), older `.json` files still import; only theme.json and the image it names are read), `theme-customizer-controls.js` (picker drag captured on the SV box with its default cancelled, so it never selects text or auto-scrolls; wallpaper, sanitised `.ctme` import/export, blur 0–40px and transparency 10–100% sliders), `theme-customizer.js` (state, open/save via `registry.setTheme()`). Its title, labels and Live Preview heading take `--cx-text-primary` / `-secondary` (id-scoped, `!important`), so Connect's heading and label colours never reach it in Light.
- **Engine**: `theme-surface-adapter.js` tags unstyled light surfaces (`data-connectea-surface`/`-ink`); `theme-toggle.js` mounts `#connectea-theme-toggle`; `theme-menu.js` renders `#connectea-theme-menu` (custom themes get Edit ✎, which reopens the customizer on that theme and saves in place by id, and Delete ✕; styles in `theme-menu-actions.css`; Customize Theme... then Import Theme...); `theme-import.js` (`ConnectifyThemeImport`): `sanitize(raw)` (shared with the customizer import), `importFile(file)` saves a theme file as a custom theme (same name updates it; missing Basic tokens from Dark) and applies it, `pick()` opens the picker, `failText(err)` (the import alert names the reason and logs it); files are read with `ConnectifyThemeCtme.unpackFile` (a data URL string via `FileReader`, since Firefox MV3 content scripts may not read page-owned buffers from `arrayBuffer()` or a `Response`); `theme.js` (`ConnectifyTheme`) applies themes on `connectea:themechange`, disables them on login/logout and restores after sign-in; `theme-request.js` applies a theme requested from the page world (`connectify-request-theme`), which the theme audit uses because the registry is isolated-world only.

#### [`auto-login.js`](file:///Users/uwong/Downloads/2.1.14_0/src/system/auto-login.js)
- **Role**: Auto-submits login credentials on `https://login.det.wa.edu.au/*` while respecting session expiry and manual logout.
- **Key Functions**:
  - Injects "Auto-login" toggle checkbox next to the login button.
  - Detects session timeout URLs and inactivity messages; pauses auto-login and displays warning notice `(Paused: session expired)`.
  - Prevents rapid looping via a 30-second loop guard.
  - Fires only for a saved password / browser autofill once both values are readable (Chromium matches `:autofill` before releasing the password to the page; the release fires `input`, which retries); typing or pasting in a credential field disables it for that page.

### Style Sheets & Extension Configuration

#### Style Sheets
- **`src/progress/progress.css`, `compound-progress.css`, `export-view.css`**: progress graph modal (no subject heading, the pressed chip names it; ATAR Progression heading 700, chips 600, legend 400); compound subject bars; the Export view (clear rows with hairlines, primary download buttons, token-routed in dark themes).
- **`src/atar/atar.css`, `atar-compact.css`, `atar-planner.css`, `atar-estimator.css`** (in that order): calculator modal (`#connectea-atar`) base and dark mode; subject select, grade table and compact layout; planner controls (target inputs left-aligned), top-four selector and Back to top button; Goals / Estimator mode tabs (type restored over `#connectea-atar button`) and Estimate Grade inputs.
- **[`progress.css`](file:///Users/uwong/Downloads/2.1.14_0/src/progress/progress.css)**: Progress graph modal layout and SVG stroke/fill rules.
- **`src/system/touch-targets.css`** (all-pages group, after `theme.css`; touchscreens only, `any-pointer: coarse`, and only under `html:not([data-cx-mouse])`: `pointer-kind.js` sets it on the first mouse input, a touch clears it): Connectify controls at least 44px each way by growing in the layout (no overlap); handle 44px wide (`--cx-handle-width`); the theme button and its chevron take taps over the bar's height only, never sideways.
- **`src/sidebar/styles/`**: drawer, handle/menu, tool menu, weakness/types, outcome meter/filter, notifications, predictor and settings/progress-pill stylesheets (readable, one concern per file).
- **`src/theme/styles/`**: the theme cascade, one concern per file (<= 250 lines), loaded in manifest order: tokens and palettes (`theme-tokens.css`, `theme-wallpaper-layer.css` (blurred, dimmed or brightened wallpaper layer), `theme-surface-base.css`, `theme-component-base.css`), core and navigation, tiles, cards and task rows, controls and buttons, icon buttons, dialog surface, material, feed (notice and dialog text in the primary ink, feed cards in the secondary), menus, `theme-user-menu.css` (top-right user area: avatar button clear on the bar, dropdown header and Sign Out clear on the popup in the theme ink, Sign Out keeps Connect's geometry, colours only), tables and dialogs, navigation and discussions, surfaces and display scaling, customizer, `theme-glass-panels.css` (Liquid Glass curvature for the notice card host, Library table wrapper), `theme-empty-states.css` and `theme-control-bars.css` (all themes: centred empty states, paginators and the Select All row clear on the page), `theme-glass-surface.css` (banner, category bars, Library toolbar, Select All row, headings and empty states have no panel) and `theme-glass-class-pages.css` (Class page rules: Content canvas, Learners table, Summary tiles/calendar), `theme-glass-task-rows.css` (assessment row statistics strip, overall stats panel and marks/boxplot column as tints inside the glass tile, primary ink), `theme-surface-nesting.css` (every dark theme: inner layers of a surface are clear, incl. the article wrapper around home page tiles and promos inside tiles), `theme-glass-reading.css` (notice/discussion views: page, frame and view clear, text on the wallpaper), `theme-glass-nesting.css` (one surface per block: header canvas clear, top bars and side menu blur, service bar container clear, lists/tables/rows/cells inside surfaces clear), `theme-light-tone.css` (data colours re-inked under `data-connectea-tone="light"`, set by `theme-custom-tokens.js` when the theme's text is dark; the Weaknesses plot turns clear with ink labels and OKLCH 0.30 scores; glass dialog backdrops brighten, white 45%, instead of the navy dim), `theme-alert-tiles.css` (important tiles such as the Maintenance Notice keep a red header tint, divider and icons), and finally `theme.css` (Liquid Glass-only geometry, tiles clipped with `overflow: clip`, opaque solid-theme panels, clear outline wrappers around tiles in every dark theme). Every selector is scoped to a theme hook (Test 153); ancestors are named by class, never `[class*=...]` (Test 219: a substring ancestor made each Connect class change restyle the whole subtree); the dark hook is `.connectea-dark:not(cx-n)`, never `:is(html.connectea-dark, body.connectea-dark, .connectea-dark)` (same match and 0,1,1 specificity, but the ancestor filter can reject it), and no `:nth-child` sits on a generic `span` / `div` subject (Test 269). Every list that is a compound's only key is expanded, one exact selector per argument (`scripts/expand-is.js`, Test 270: specificity padded with `:not(.cx-n)` / `:not(#cx-n)`, complex arguments kept in `:is()`, `<html>`/`<body>` hook lists kept whole), so Chrome buckets each rule by a class, id or tag; sheets past 250 lines continue in `<name>-2.css`, `-3`.
